# 黑米姐姐 API

后端采用 NestJS 模块化单体架构。MVP 阶段所有业务模块部署为一个服务，但通过清晰的模块边界控制依赖，为后续拆分和扩展保留空间。

## 目录结构

```text
src/
├── common/          # 跨模块公共类型、异常、常量和基础能力
├── config/          # 应用配置与环境变量读取
├── database/        # 数据库连接、迁移与仓储实现
├── integrations/    # 微信、对象存储等第三方能力
├── jobs/            # 定时任务与异步任务
├── modules/         # 按业务域划分的核心模块
├── observability/   # 日志、指标与链路追踪
├── app.module.ts    # 根模块
└── main.ts          # 应用启动入口
```

## 模块依赖原则

1. 业务模块不能直接依赖第三方 SDK，应通过 `integrations/` 提供的适配层调用。
2. Controller 只负责协议转换和参数接收，业务规则放在 Service 或领域服务中。
3. 数据访问通过仓储接口隔离，业务模块不直接拼接 SQL。
4. 订单、库存、支付、退款等关键操作必须支持幂等和状态校验。
5. 模块之间优先通过公开 Service 或事件通信，不直接访问对方内部文件。
